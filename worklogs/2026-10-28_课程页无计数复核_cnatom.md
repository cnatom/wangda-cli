# 课程页无计数时按专题卡片复核

## 状态

已修复：整课节次在课程页显示全部「已完成」、但该版页面没有「完成 x 节 / 共 y 节」计数（只显示 `进度: 0%`）时，`run_course` 原本要空等满 `CREDIT_WAIT_S`（600s）再返回失败，队列随即 `unconfirmed` 中止；期间平台若把标签页自动切到下一门课，还会被当成 `course_mismatch` 重新进入并从 0 重播最后一节，每轮白烧一整节。

改动：

- `src/wangda/engine.py`：新增 `CourseResult`（bool 语义不变，附带 `reason`）、`COUNTER_ABSENT_WAIT_S = 90`；`course_unconfirmed` 增加 `reason`（`counter_absent` / `counter_incomplete`）；计数整版缺失时只等 90s；节次已全部完成后若标签页切到别的课程，记 `course_page_advanced` 直接收尾，不再重进重播。
- `src/wangda/adapter.py`：新增 `course_card_done()`，仅当 `reason` 属于 `counter_absent` / `page_advanced` 时读专题页复核该课卡片是否「已完成」，是则记 `course_card_rescue` 继续；计数存在但未到 x/x 的失败仍按失败处理，不放宽确认口径。
- `skills/wangda/SKILL.md`：补一条 pitfall 说明两种原因的判定与处置。
- 测试：`tests/test_engine_replay.py` 3 例（无计数快速超时、计数不全仍等满、完成后自动切课不重播），`tests/test_adapter.py` 3 例（卡片已完成可兜底、卡片未完成仍失败、计数不全不兜底）。

## 证据

- 真实页面（课程 97915491 坚持推进作风建设常态化长效化）`SECTION_STATE`：`cnt=4, allDone=true, stat` 全部「视频 已完成」，但 `prog=""`，正文只有「进度: 0%」。

- 运行日志 `events-7f2eea12…jsonl`：`course_mismatch cid=729a1723…` 出现在 15:37、15:47、16:00，间隔约等于 843s/1.5，对应每次把最后一节从 0 重播；16:01 `course_unconfirmed` + `result unconfirmed`，队列在第一个链接即中止。

## 如何继续

- 本 PR 与 `docs/skill-self-improvement-pr` 都未合并；本地若要先跑新逻辑，用 `uv tool install --force 'git+https://github.com/cnatom/wangda-cli.git@fix/course-card-confirmation'` 从分支安装。
- `进度: 0%` 的语义仍未确认（疑似播放器当前位置而非课程完成度），后续若发现平台提供别的完成度字段，可把 `course_card_done` 的复核做成更直接的正向信号。
