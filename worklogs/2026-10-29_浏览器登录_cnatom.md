# 浏览器登录改回默认

## 状态

已完成并在真机验证。默认登录方式从「纯协议 `wanda auth`」改回「浏览器手动登录 `wanda login`」，版本 0.7.0 → 0.7.2，main 已合入（`1d5f4f8`、`0ff303c`、`cee3b45`）。

`wanda login` 的行为：用专用 profile 打开一扇**不带 `--remote-debugging-port`** 的普通 Chrome 窗口 → 本人在里面完成短信登录 → 关窗 → CLI 附着同一 profile 读出网页自己写的 `localStorage["token"]` → 写入 `<data-dir>/session.json`（0600，`source: browser`）。`wanda auth` 协议登录保留，作为无图形界面主机的备选。

**顺序不能颠倒，这是硬约束**：`/oauth/` 登录页检测已连接的 devtools，带调试端口的窗口点「获取验证码」会把自己跳成 `about:blank`（`You don't have permission to use DEVTOOL!【type = 6】`）。所以登录必须发生在没有调试端口的窗口里，CLI 只能事后附着。

**采纳判定只看可见状态，不看 token 是否存在**：profile 里残留的过期 token 在 `about:blank` 上照样读得出来（空白页继承 opener 的源）。必须同时满足「在 wangda.chinamobile.com 上」「没有登录墙」「正文非空」才认，否则 `LoginRequired`。

## 踩到的坑

1. Chrome 关掉最后一个窗口后**进程仍在后台常驻**，只靠 `Popen.poll()` 判断「窗口已关」会一直等到超时（实测卡了 3 分钟没接管）。改为同时观察 profile 的 `*/Local Storage/leveldb/*` 最近修改时间：应用写入 token 也结束等待，留 3 秒落盘，再收掉残留进程接管。
2. 排查时用 headless 附着读到了「token 存在但 href 是 `about:blank`」的假登录态，直接印证了上面那条判定必要性。

## 证据

- `pytest -q`：140 passed / 2 skipped；`ruff check src tests` 全绿。
- 真机：`wanda login` 打开窗口 → 本人登录 → 关窗；接管阶段打印 `href: https://wangda.chinamobile.com/#/home`、`token: present`、`signed_in: True`，`doctor` 显示 `fresh: True`。
- 用例覆盖：关窗后接管、残留 token 不采纳、`about:blank` 不算会话、窗口不关会超时并终止、storage 推进则提前接管。

## 如何继续

- 登录仍然每约 4 小时需要一次新的短信码（implicit 授权无 refresh_token，profile 里也没有可续期的长期 cookie：只有 `orgId` / `configId` / `timestamp`）。账号**没有密码登录**，所以「存静态密码静默重登」这条路不存在。
- 想降低打扰只能调 `session_wait_seconds`（默认 6 小时），让队列在没人管的时候一直挂着等登录，而不是到点退出。
