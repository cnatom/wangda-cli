# 常驻队列（P4）

## 状态

已完成 `--watch`：一轮跑完不退出，未完成的链接重新排队复查，最多 `watch_max_passes` 轮。token 过期时不再直接失败，而是停在 `waiting_login` 原地等新 token，用户重跑 `wanda auth` 后同一队列自动继续。

**重要结论：token 无法静默续期。** 平台用 implicit 授权（`response_type=token`），`oauth_main.js` 与 `main.js` 里 `refresh_token` / `refreshToken` 出现 0 次，没有 refresh 端点可用。所以“自动续”只能做到“到期前原地等待 + 热加载新会话”，需要用户每约 4 小时给一次短信验证码。这是协议限制，不是实现偷懒。

改动文件：`src/wangda/runner.py`（拆出 `pass_over`，加 watch 循环、`wait_for_session`、`watch_pause`、`session_usable`）、`src/wangda/config.py`（watch / watch_interval / watch_max_passes / session_wait_seconds）、`src/wangda/cli.py`（`--watch`、`--watch-interval`，`doctor` 增加 `expires_in_remaining`）、`tests/test_runner.py`（4 例）、`config.example.toml`、`docs/usage.md`、`skills/wangda/SKILL.md`（0.6.0）。

## 行为

| 场景 | 非 watch | watch |
|---|---|---|
| 一轮结束仍有未完成 | 直接收尾 failed/unconfirmed | 等 `watch_interval` 后重新排队，最多 `watch_max_passes` 轮 |
| token 过期 | `waiting_login` 退出 | 状态 `waiting_login` + `reason=session_expired_waiting_for_auth`，等待新 token，最多 `session_wait_seconds` |
| token 未变化（用户没重登） | — | 等到上限后按 `waiting_login` 收尾 |
| 没有 session.json（旧 cookie 流程） | 不变 | 不进入等待，按原逻辑收尾，不会挂住 |

## 证据

- `pytest -q` 116 passed / 2 skipped；`ruff check src tests` 全绿。
- 新增用例：watch 重试到 completed（`pass == 2`）、`watch_max_passes=2` 时按 unconfirmed 收尾、写新 token 后自动继续（旧 token 已过期，worker 只在拿到新 token 后跑一次）、无 session 时不挂住。
- `wanda doctor` 实测输出 `session: {'present': True, 'fresh': True, 'expires_in_remaining': 12095}`。

## 如何继续

- 无人值守验收：本机跑 `wanda run <URL…> --watch --background --json`，跨过一次 token 过期（约 4 小时）确认会自动续上；这一步至少需要半天，尚未做。
- 若以后平台改成 authorization code + refresh_token，`auth.py` 里加 `renew()` 即可，watch 循环已经留好“新 token 到达”的判据。
- `watch_max_passes` 是防跑飞的闸门；真要做到“跑到全部完成”，把它调大（最大 100），不要去掉。
